## 1. 配信の開始（slug 発行）

1. 大会アプリの順位タブ →「📡 参加者向けライブ配信（任意）」を開く。
2. **表示名モードを選ぶ**（§4 参照。既定は「姓＋番号のみ」）。
3. 「📡 ライブ配信を開始」を押す（要ログイン＝クラウド管理ページ app/ でログイン済みであること）。
4. 確認ダイアログの内容（インターネット公開・掲示物への告知）を読んで OK。
5. 発行された **QR と URL が表示される**。QR を印刷して受付・会場に掲示する（§3 の告知文言を必ず併記）。
6. ヘッダ直下に「📡 配信中」バーが出続けること・保存のたびに「最終送信 hh:mm:ss（成功）」が更新されることを確認する。

> 公開コード（slug）は大会ごとに発行される使い捨ての推測困難な文字列（実質 bearer secret）。
> URL を知っている人だけが閲覧でき、公開中の配信を一覧・列挙することはできない（設計 §4.2）。

## 2. 大会終了時の停止（必須・終了チェックリスト）

**大会終了操作のチェックリストに「配信停止」を必ず含める**（設計 §4.2 Should Fix #2）。

- [ ] 結果発表が終わったら「⏹ 配信を停止」（配信中バー or 配信セクション）を押す。
- [ ] ステータスに「配信を停止しました（掲示したQR/URLは無効になりました）」が出ることを確認。
- [ ] 掲示した QR を回収する（撮影で持ち帰られていても、停止後は旧 URL で何も見えない）。
- [ ] 停止時にエラーが出た場合: 電波の良い場所で再度停止を押す。それでも失敗する場合は Supabase ダッシュボードで
      `public_live_snapshots` の該当行の `is_public` を `false` にする（最終手段）。

> 停止後、旧 slug での `get_live_snapshot` は何も返さない（pgtest で担保・受入 #18）。

## 3. QR 掲示物（入口 J2）と公開の告知（受入 #17）

掲示物には**必ず**以下を含める:

```
📱 ライブ戦況はこちら（スマホで QR を読み取ってください）
[QR]
※ 本大会では参加者の表示名（<フルネーム or 姓＋番号> ）・対戦結果・順位を
   インターネット上で公開しています。公開を望まない方は受付までお申し出ください。
※ スマホをお持ちでない方は受付のタブレットでご覧になれます。
```

- 表示名モードに合わせて `<フルネーム or 姓＋番号>` を書き換える。
- 未成年（会費区分「中学生以下」等）が参加するため、**告知なしの掲示は禁止**。
- 公開を望まない参加者がいた場合の運用: 表示名モードを「姓＋番号のみ」へ変更して配信を開始し直す
  （§5.1 の停止→再開始。旧 URL は失効するので QR を貼り替える）。

## 4. 表示名モード（display_mode）と主催者の決定記録（受入 #17）

| モード | wire に載る表示名 | 用途 |
|---|---|---|
| `given+no`（**アプリ既定**） | 姓＋番号（例「山田（12）」。空白なし登録は先頭1文字＋番号）。よみは非公開 | 既定。告知のみで運用可 |
| `full` | フルネーム＋よみ | **主催者が告知・同意運用を明示決定した場合のみ** |

- アプリの既定選択は `given+no`＝**氏名公開を暗黙の既定にしない**（設計 §3.2）。
- `full` を使う場合、主催者は下の決定記録を埋めて本ファイル（または大会記録）に残すこと。

### 決定記録（主催者が記入）

| 項目 | 記入 |
|---|---|
| 既定の表示名モード | （例: given+no ／ full） |
| 決定者（主催者） | |
| 決定日 | |
| 告知方法 | （例: 会場掲示＋開会アナウンス） |
| 同意運用 | （例: 申込時に周知・当日申し出で匿名化） |

> **注**: 本大会としての既定値の最終決定は人間（主催者）が行う（AI は決めない）。未記入の間は
> アプリ既定の「姓＋番号のみ」で運用する。

## 5. 公開 config の配備（初回のみ・P1-c）

参加者ページは `app/config.public.js`（**コミットして GitHub Pages で公開**）を読む。

1. `app/config.public.example.js` を `app/config.public.js` にコピー。
2. Supabase の Project URL と publishable key（anon/publishable）を記入。
3. コミットして production へ反映（この鍵で可能なのは `get_live_snapshot` の実行のみ。
   秘密鍵〔service_role〕は絶対に書かない）。
4. 運営ログイン用 `app/config.js`（gitignore・非公開）とは別物。混同しない。

## 6. 受付タブレット（キオスク）設営（§5.3・受入 #8）

1. 配信開始後に表示される URL の末尾へ `&kiosk=1` を付けてタブレットのブラウザで開く
   （例: `…shogi_v4.html?live=<公開コード>&kiosk=1#scoreboard`）。
2. キオスクでは: 無操作60秒で個人ビュー/検索を解除して全体星取表へ自動復帰・タップ目標拡大・
   対応端末では画面点灯維持（Wake Lock）。
3. **Wake Lock を過信しない（P2-b）**: 端末設定で自動ロックを「なし」にし、
   iOS は「ガイドアクセス」、Android は「画面の固定」で運用すること（運用条件）。
4. 回線は会場 Wi-Fi かセルラー（運営端末とは独立。運営端末の localStorage には依存しない）。

## 7. 漏えい・誤配布時のローテーション

1. 「⏹ 配信を停止」→「📡 ライブ配信を開始」で**新しい slug を再発行**する
   （再発行時、同一クラブの旧 slug はサーバ側で自動失効する）。
2. 新しい QR を印刷して貼り替える（旧 QR は回収）。

## 9. トラブルシュート

| 症状 | 対処 |
|---|---|
| 配信中バーが「⚠ 送信に失敗しました」 | 電波を確認。次の保存で自動再送。運営アプリは影響なし（fail-soft） |
| 参加者画面が「配信設定が見つかりません」 | `app/config.public.js` 未配備（§5） |
| 参加者画面が「配信が見つかりません」 | 停止済み or 旧 QR。現在の QR/URL を再掲示 |
| 開始時「ログインしてから」 | クラウド管理ページ（app/）でログインしてから開始 |
| 更新が止まって見える | 「最終更新」時刻を確認。画面を一度閉じて開き直すと再取得（focus 再取得） |
