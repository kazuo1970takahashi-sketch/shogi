## 0. 現状の棚卸し — 既に持っている土台

汎用化はゼロからではない。以下は**既に実装済み**で、そのまま全国展開の土台になる。

| 土台 | 現状 |
|---|---|
| 大会運営コア | 受付・可変クラス・スイス式ペアリング・順位（勝数→SOS→SODOS→直接対決）・星取表・報告書印刷。沼津で実運用実績あり（本番 ?v=54） |
| ローカルファースト | 単一 HTML + localStorage・オフライン堅牢・normalize 往復恒等・テストハーネス（PASS 66 / WARN=0） |
| PWA | manifest + sw.js 実装済み。「1 PWA・当日アプリがホーム・app/ は内部ページ」方針確定 |
| クラウド多テナント | app/ + Supabase。clubs / members / organizers、RLS でテナント隔離、マジックリンク認証。**構造上すでに「複数支部」対応** |
| 閲覧専用ビュー | `?view=scoreboard` のスマホ星取表（read-only・自動更新）。ただし**同一ブラウザ限定**＝配信の種 |
| 大会履歴 | アーカイブ蓄積・履歴タブ。過去大会の Excel 一括取り込み（B-4）完了済＝クラウドに 2024〜2026 年度の 98名/22大会/359成績・通年集計 UI あり |

## 1. 汎用化を阻んでいるもの（沼津固有の硬結合）

`shogi_v4.html` 内に「沼津」が 48 箇所。実体は次の 3 群に集約できる。

1. **報告書・大会テンプレート**（行 917 付近の `state.report` 既定値）
   - title「沼津支部月例将棋大会」／organizer「日本将棋連盟沼津支部」／place「労政会館」／fax／officeName／accountingNote／持ち時間既定（25分切れ負け・秒読み30秒）
2. **会費規定**（行 677 `getFee(member, grade)`）
   - 区分（支部員/一般 × 一般/中学生以下/女性）と金額（500/1000/0/500円）がコード埋め込み。区分の**種類そのもの**が支部ごとに異なりうる
3. **UI 文言・ランディング**（`<title>`・ヘッダ・ヘルプ文・index.html の参加費表/賞品/ルール説明）

技術的制約（変えない前提で設計する）: 単一 HTML・ES5・グローバル state・localStorage 約5MB。
9項目ルールにより大規模リファクタは不可 → **汎用化は「設定の外出し」という追加型で実現する**。

## 2. 施策の全体像 — 4 つのテーマ

```
テーマ1 汎用化        : 沼津固有値を設定化（どの大会でも使える）
テーマ2 全国展開      : 支部/大会のセルフオンボーディング（誰でも始められる）
テーマ3 リアルタイム共有: 星取表を会場外・他端末へ配信（観戦の入口）
テーマ4 参加者体験    : 対局者・観戦者向けの「楽しい」機能
```

### テーマ1: 大会設定の外出し（汎用化の最小核）

- **G1-a 大会プロファイル**: `state.report` 既定値＋大会名＋持ち時間を「大会設定」オブジェクトに集約し、設定画面（既存の報告書タブ拡張）で編集可能に。既定値＝現沼津値なので**沼津運用は無改変**。
- **G1-b 会費テーブルの設定化**: `getFee` を「区分リスト × 金額」のデータ駆動に。既定＝現行 4 区分。区分の追加/名称変更/金額変更を UI から可能に（FEE-JOSEI のような改修が設定変更で済むようになる）。
- **G1-c 文言の脱・沼津**: ヘッダ/ヘルプ/印刷物の「沼津支部」を大会プロファイル参照に置換。
- **G1-d 設定の保存と共有**: 大会プロファイルを localStorage 保存＋JSON エクスポート/インポート（既存の保存3系統に「設定」を追加）。将来は Supabase `clubs` に club 別設定として持たせ、ログインで自動ロード。

> 実装順の勘所: G1-a/b は「既定値がハードコード → 既定値が設定オブジェクト」の追加型変更で、
> 9項目ルールと相性が良い。**汎用化の最初の PR はここ**。

### テーマ2: 全国展開（セルフオンボーディング）

- **G2-a 初回セットアップウィザード**: 初回起動時に「大会名・主催・会費・クラス数・回戦数」を聞いて大会プロファイルを生成。テンプレート（支部月例/子ども大会/職団戦風など）から選択。
- **G2-b ランディングの汎用化**: index.html の沼津固有内容（参加費表・賞品）を製品紹介＋デモに差し替え。※ルール8（index.html 原則無改変）に触れるため**別リリース判断が必要**。
- **G2-c 配布モデルの決定**（意思決定事項）:
  - 案A: 中央ホスティング1本（今の GitHub Pages を全国共用。club はクラウド設定で分離）— 運用が軽い。推奨
  - 案B: 各支部が fork して自分の Pages に置く — 完全自律だが更新配布が課題
- **G2-d ドキュメント整備**: 導入ガイド・運営マニュアル（manual_sp/manual_print）から沼津前提を除去し、汎用マニュアル化。「他支部で1回使ってもらうパイロット」を早期に設定する。
- **G2-e 名前とブランド**: 「SHOGI-TOUR」を製品名として立てる（アイコン・短い紹介ページ・スクリーンショット）。

### テーマ3: リアルタイム共有（観戦の技術基盤）

現在の `?view=scoreboard` は **localStorage 経由＝運営者と同一ブラウザ限定**。これを他端末に広げるのが配信の第一歩。

- **G3-a 大会ライブページ（read-only 公開）**: 運営アプリが対局結果確定時に Supabase へ大会スナップショット（星取表・順位・進行中の手合い）を push し、`app/` 側に**誰でも見られる閲覧ページ**を新設。会場に QR コードを掲示 → 参加者・観戦者が自分のスマホで順位を見られる。
  - 既存資産の再利用: scoreboard ビューの描画ロジック＋Supabase 基盤＋「新機能は app/ に置く」PWA 方針に合致
  - オフライン原則を壊さない: push は fail-soft（ネット不通でも当日運営は無影響）
- **G3-b リアルタイム更新**: Supabase Realtime（またはポーリング）で結果入力の数秒後に観戦側へ反映。「次の対局はあの卓だ」が会場のどこからでも分かる状態。
- **G3-c 公開範囲制御**: 大会ごとに公開/限定公開（URL トークン）/非公開。氏名の扱い（フルネーム/姓のみ/ニックネーム）を大会設定で選べるようにする（**個人情報配慮は配信の前提条件**）。

### テーマ4: 対局者・観戦者が楽しめる機能

G3 のライブページの上に載せる。優先度順に:

- **G4-a マイページ（対局者向け）**: エントリー番号か QR で自分を選ぶと「次の対戦相手・卓番号・現在の成績・順位」だけが大きく出る。呼び出し掲示の代替。**当日体験の改善効果が最も大きい**
- **G4-b 大会の見せ場演出**: 優勝ライン表示（残り○勝で優勝）、全勝対決のハイライト、最終戦の順位変動可能性。スイス式の「終盤のドラマ」を可視化する
- **G4-c 個人通算成績**: 大会履歴（アーカイブ）を使い、参加者ごとの通算勝率・対戦成績・レーティング風指標。月例大会の**継続参加インセンティブ**になる
- **G4-d 表彰・結果共有**: 大会終了時に結果画像（SNS 共有用）を自動生成。参加賞状 PDF
- **G4-e 動画配信連携**: 注目対局の YouTube Live 埋め込み枠をライブページに用意（配信自体は運営が既存ツールで実施。アプリは「場」を提供）
- **G4-f 将来構想**: 対局時計機能・棋譜入力/中継は工数大。需要を見てから（本ロードマップでは対象外と明記）

## 3. 推奨フェーズ分けと順序

| フェーズ | 内容 | 依存 | 出口条件 |
|---|---|---|---|
| **P1 汎用化コア** | G1-a/b/c/d（大会プロファイル・会費設定化） | なし | 沼津以外の架空大会を設定だけで運営できる |
| **P2 ライブページ MVP** | G3-a（スナップショット push ＋ 公開閲覧ページ）＋ G3-c 最小（URL トークン＋氏名表示設定） | Supabase 基盤（あり） | 会場 QR から参加者が自分のスマホで順位を見られる |
| **P3 オンボーディング** | G2-a/c/d（ウィザード・配布モデル・汎用マニュアル）＋ 他支部パイロット 1 件 | P1 | 沼津メンバーの手伝いなしで他支部が大会を 1 回完走 |
| **P4 参加者体験** | G4-a/b（マイページ・見せ場演出）→ G3-b（リアルタイム化） | P2 | 対局者の過半が当日ライブページを開く |
| **P5 楽しさ拡張** | G4-c/d/e（通算成績・共有画像・配信枠） | P4（通算成績の土台＝B-4 取り込み済データ・通年集計は既に app/ にあり） | — |

並行して継続するもの: 規約・プライバシー方針（連盟回答待ち）・未成年公開名マスク（P0・G3 公開機能の前提）・localStorage quota 対策（A-10。履歴増加で顕在化するため P2〜P3 の間に IndexedDB 退避を検討）。

## 4. 変えないこと（設計原則の再確認）

1. **当日運営のオフライン堅牢性が最優先**。配信・クラウドは全て fail-soft の追加レイヤー
2. `shogi_v4.html` は追加/最小改変中心。観戦・配信系の新画面は **app/ 側に置く**（PWA 方針どおり）
3. 汎用化＝「既定値の設定化」であり、リファクタ・挙動変更と混ぜない（9項目ルール維持）
4. 実データ・実氏名はテスト/デモに使わない。公開機能は氏名表示制御を先に作る

## 5. 直近の意思決定事項（人間判断が必要）
