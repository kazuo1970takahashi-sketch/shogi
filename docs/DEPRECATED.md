# DEPRECATED — 廃止した概念の一覧（DOC-GUARDS-001 / #951）

アプリから**概念ごと外した**ものをここに 1 か所で持つ。設計文書（`docs/specs/`・`docs/notes/`・
`docs/REFERENCE.md` 等）は過去の要求を書いたまま残るので、読者が「これはまだ生きている要求か」を
迷わないための印。

## 使い方（2 つだけ）

1. 概念を廃止したら、下の `json` ブロックに 1 件足す。**一覧はこのブロックだけ**（人向けの表は置かない＝
   機械の正本と人の読む一覧が食い違う余地を作らない）。
2. その概念の語彙を含む文書ファイルは、**先頭 10 行に** 次の宣言を置く（md / html どちらでも不可視）:

   ```html
   <!-- deprecated: table-no -->
   ```

   複数なら `<!-- deprecated: table-no, foo-bar -->`。

検査器 `test/test_doc_deprecated_guard_951.js` が固定するのは次の 3 つ**だけ**:

| 赤になる条件 | 意味 |
|---|---|
| (a) 語彙あり・宣言なし | 廃止概念を語る文書に印が無い |
| (b) 宣言あり・語彙なし | 印が腐っている（語彙が消えたのに印だけ残った） |
| (c) 宣言の id がこの一覧に無い | 一覧に登録せずに印だけ書いた |

行ごとの生死（引用・取り消し線・近接の失効注記）は**判定しない**。読者は先頭の宣言で
「この文書は廃止概念を含む」と分かり、本文の失効注記は人が読む。文書側の免除規則を
足さないことで、#946（PR）で Codex が示した抜け道（引用ブロック・`#941` の引用・近接・
取り消し線の同一行）を**持たない**。

**Markdown のコード文脈は認識しない**（作者裁定 2026-09-05）。先頭 10 行に `<!-- deprecated: … -->` が
あれば、フェンス内の例示であっても宣言として数える（そこにあれば読者にも見える）。11 行目以降にある
宣言は無視する（赤にもしない）。検査器を Markdown パーサにしない＝フェンスの種類・行頭・入れ子を
追いかけない。語彙の照合は本文全体に対して行い、宣言コメントそのものだけを除く。

対象 = `docs/specs/**`・`docs/notes/**`・`docs/REFERENCE.md`・`docs/STYLE-GUIDE.md`・
`docs/manual_*.html`・`docs/install_guide.html`。
除外 = `docs/CHANGELOG.md`・`docs/changelog.d/`・`docs/ai-ops/`・このファイル（履歴と工程文書は
廃止概念を語って当然）。

## 一覧（検査器が読む唯一のブロック）

各項目の意味: `id` = 宣言に書く識別子／`concept` = 何を廃止したか／`issue` = 裁定の Issue／
`decided` = 日付／`vocabulary` = JavaScript の正規表現（`u` フラグ）。**「数としての卓」（残り 3 卓・
全15卓・1卓追加）に当たらない語だけ**を置く／`vocabulary_note` = 語彙の人向け説明（正規表現と同じ範囲を書く）／
`note` = 裁定の要点。

```json
[
  {
    "id": "table-no",
    "concept": "卓番号（「第 N 卓」・対局カードのバッジ・印刷の卓番・個人ビューの卓番・sbFindCurrentMatch の table）",
    "issue": 941,
    "decided": "2026-09-01",
    "vocabulary": ["卓番", "第\\s*(?:[0-9０-９]+|[NnＮ]|\\(i\\+1\\))\\s*卓", "table_no", "tableNo", "`table`"],
    "vocabulary_note": "卓番／第 N 卓（N は数字・N/n/Ｎ・(i+1)）／table_no／tableNo／コード書式の `table`",
    "note": "沼津の運用で使っていないため概念ごと外す（TABLE-NO-REMOVE-001）。他所で必要になったら「卓番を使う/使わない」の設定として足す。数・単位としての「卓」は据え置き。"
  }
]
```
