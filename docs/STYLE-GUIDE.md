## 1. 色（意味色システム）

意味のある色は以下の4色のみ。**これ以外の新色を追加しない**（グレー系の補助色は既存値を流用）。

| 意味 | 色 | 既存定義（shogi_v4.html） |
|---|---|---|
| primary（主要・進行・ブランド） | `#1F3864`（紺） | `.btn-primary` L39・`.header` L26・`h2` L33・`theme-color` L10 |
| ok / success（成功・完了・準備OK） | `#27500A` 文字・`#eaf3de` 地・`#97c459` 枠 | `.btn-success` L40・`.alert-ok` L45 |
| danger（破壊・不可逆） | `#A32D2D` | `.btn-danger` L41 |
| warn（注意・未完了・要確認） | `#633806` 文字・`#faeeda` 地・`#EF9F27` 枠 | `.alert-warn` L46 |

- **app/ も primary を `#1F3864` に統一する**（現状 `--primary:#2b6cb0` は不適合 → §9）。
  app/ は CSS 変数化済みなので `:root` の1行変更で済む。
- 色の指定は class で行う。**インライン style での新規色指定は禁止**（§2 参照）。

## 2. ボタン

### 2.1 種別（既存 class 体系を正とする）

| 用途 | class | 例 |
|---|---|---|
| 通常操作（既定） | なし（白ベース `button` L38） | 編集・閉じる・キャンセル |
| 主要導線（その画面で一番押してほしい） | `.btn-primary` | 対局開始・確定して次へ |
| 破壊的・不可逆 | `.btn-danger` | 全リセット・削除 |
| 完了・成功系の確定 | `.btn-success` | （使用は限定的に） |
| 補助・行内の小操作 | `.btn-sm` | 行内の編集/削除・「？ ヘルプ」 |

### 2.2 配置・寸法の原則（実運用で確立済みのルールを明文化）

1. **縦積みの同格ボタンは全幅（`width:100%`）で揃える**。横並びはオート幅（?v=39/?v=45 で確立）。
2. タップ目標は **min-height 44px** を目標とする（現状 `.player-row-buttons button` のみ L64 → §9 で全面化）。
3. 1画面の常時表示ボタンは**7個以内**を目安。超えるなら低頻度・危険操作を `<details>` に格納する（§7）。
4. **インライン style は position/margin 等のレイアウト微調整のみ許容**。色・フォント・枠は class で。

### 2.3 絵文字ポリシー（二値ルール）

- **付ける**: 別画面・別系統へ渡る導線（📱スマホ星取表・☁クラウド・📋名簿を更新・📥取り込み・📂インポート・⚙メンテナンス・⋯その他・↩元に戻す）。先頭に1個のみ。
- **付けない**: 画面内で完結する通常操作（追加・削除・編集・確定・閉じる・開始）。
- 判断基準:「押すと文脈が切り替わる／外部に何かが出ていくボタンか？」— Yes なら絵文字可。

## 3. 通知・確認の4分類ルール（最重要）

現状 alert 61・confirm 28・showMsg 119・setStatus 52 が混在。今後は次の4分類で選ぶ。

| # | 場面 | 手段 | 備考 |
|---|---|---|---|
| N1 | **破壊的・不可逆操作の事前確認** | `confirm()` | 文体は §4.2。危険語（作り直す/破棄/削除/消える）を必ず含める |
| N2 | **操作の成功** | `showToast()`（1.8秒自動消滅・L4741）または `showMsg(text,'ok')` | **成功に alert を使わない**（新規コードで禁止） |
| N3 | **注意・警告（読ませたいが止めない）** | `showMsg(text,'warn')` / `alert-warn` ボックス（画面内常設） | 「操作はブロックされません」原則（fail-soft） |
| N4 | **進行状況（クラウド等の非同期）** | `setStatus(msg,color)` | 完了/失敗も status 行で。色は §1 の意味色 |

- **例外（alert が正当な唯一のケース）**: データ保存失敗などユーザーが必ず認知すべき致命的事象。
  可能なら常設バナー（`#storage-warn` 方式・?v=55）を併用する。
- `console.warn` は開発者向け情報のみ（ユーザー通知の代替にしない）。
- 既存の alert 61 箇所は一括置換しない。**タブ単位の小スライス**で N2/N3 へ移行する（§9）。

## 4. 文言

### 4.1 用語辞書（この呼称以外を使わない）

| 正式呼称 | 意味 | 使ってはいけない揺れ |
|---|---|---|
| 自動保存 | localStorage への当日データ保存 | 「保存」単独 |
| 📋 名簿を更新 | 当日参加者を支部マスタへ同期 | 名簿に反映・コピー |
| バックアップ | JSON ファイルへの控え出力（shogi_backup_*.json） | エクスポート・保存 |
| ☁ クラウドへ送信 / ☁ クラウドから取得 | Supabase との push / pull | 同期・アップロード |
| 参加者 | 当日大会にエントリーした人（player） | 選手・会員（当日文脈で） |
| 会員 / 名簿（支部マスタ） | 支部マスタ上の人（member） | メンバー・マスター |
| 部分開始 | 来た人から1局目を始める運用（FRP） | 逐次手合い・途中開始 |
| 待機 | 部分開始で未割当のまま残る人（不戦勝ではない） | bye・不戦 |
| 棄権 | 途中離脱（過去成績は残る） | 辞退・リタイア |

- ボタンラベルは**名詞止め or 「〜する」**で統一（「〜します」にしない）。
- 説明文・ヘルプは です・ます調。

### 4.2 confirm 文体テンプレート

「（何が起きるか）。（失われるもの/戻せないこと）。よろしいですか？」

例（既存の良例・?v=54 系）:「現在の組み合わせをすべて作り直します。今ある手合いは破棄され、全員をペアし直します。よろしいですか？」

### 4.3 メッセージの原則

- 失敗時は**次の行動を1つ添える**（例:「『バックアップ』でデータを控えてください」）。
- 由来に依存した断定をしない（例: 部分開始か通常開始かを推測して書かない — 004 設計の教訓）。
- 生のエラー文字列は出さない。平易文言＋詳細は console.warn（?v=53 で確立）。

## 5. ヘルプ（HELP_TEXTS 定石 = #307）

- 見出し脇に「？ ヘルプ」（`btn-sm`）→ `openHelpModal(topic)`。
- topic は固定文字列・escapeHtml 経由・1スライス=1画面。
- 現行 topic: first-round / report / reg / standings / master / save-warning /
  tournament（対局管理全般・?v=56）/
  cloud（送信/取得の意味と失敗時の影響・順位タブ送信ボタン脇と大会履歴クラウド見出し脇で1 topic 共用・?v=56）。
- 撤去済み topic: save-systems（保存4系統の説明・?v=56 新設 → SAVE-STATUS-BAR-REMOVE-001/#716 で撤去。
  唯一の導線だった保存状態バーの撤去に追随。「復旧できるのはバックアップだけ」の教育は save-warning＋backup-nudge が担当）。

## 6. レイアウト構造

- 画面 = 5タブ（`.tab`）。タブ内はテーマごとに `<div class="section">` で区切る（**閉じタグ省略は仕様**・CLAUDE.md ルール3）。
- 見出しは `h2`（primary 下線・L33）。section 内に h2 は1つ。
- スマホ/PC 分岐は既存の `window.innerWidth<600` に揃える（独自ブレークポイントを増やさない）。
- レスポンシブ必須（作者は Mac でも検証する — ?v=32 の教訓）。

## 7. details 格納パターン（ごちゃつき防止の標準手段）

低頻度・準備系・危険系の操作は常時表示せず `<details>` に格納する。
成功例: 「⚙ 名簿のメンテナンス」（?v=41）・「⋯ その他」危険リセット（?v=30）。
格納しても**ボタン id・bind は不変**にできる（HTML 再配置のみ・低リスク）のがこのパターンの利点。

## 8. 運用（このガイドの回し方）

1. **新規・変更スライスの設計メモに「STYLE-GUIDE 準拠」チェック欄を設ける**（該当 §番号を記載）。
2. レビュー（Codex / Claude レビューア）は本ガイド違反を **P2（Should Fix）** として指摘する。
3. ガイド自体の変更は docs-only PR（作者承認必須）。実装スライスと混ぜない。
4. 本ガイドと実装が食い違ったら**ガイドが正**（実装側を移行バックログに積む）。ただし実運用で
  ガイドが不便と分かったらガイドを直す（現場優先）。

## 10. 入力欄の標準（INPUT-STD-001 / #715・スマホ入力総点検 2026-07-09 由来）

スマホ（iPhone Safari / ホーム画面PWA）運用を前提に、入力を受ける要素は以下を必須とする。

### 10.1 フォントサイズ（iOS 自動ズーム防止）

- **input / select / textarea の computed font-size は 16px 以上**。16px 未満はフォーカス時に iOS がページを自動拡大し、ズームが戻らない実害がある（?v=110 時点で 13〜15px が10箇所超あり #715 で一括是正）。
- `maximum-scale=1` による抑止は**禁止**（ピンチズーム封じ＝WCAG 1.4.4 違反）。対策は各欄の 16px 化のみ。

### 10.2 属性セット（同じ役割の欄には同じ属性）

| セット | 対象 | 属性 |
|---|---|---|
| 氏名欄 | 氏名・固有名詞のテキスト入力 | `autocomplete="off"（運営端末は他人データ連続入力のため）+ autocapitalize="off" autocorrect="off" spellcheck="false"`＋`enterkeyhint`（連続入力=next / 単独・確定=done） |
| ふりがな欄 | よみがな入力 | 氏名欄セット＋`inputmode="kana"` |
| 検索欄 | 絞り込み・検索 | `enterkeyhint="search"`＋autocapitalize/autocorrect/spellcheck off（`type="search"` は任意） |
| 数値欄 | 金額・件数・キー | 増減の意味がある数値=`type="number" inputmode="numeric"` / 前ゼロ保持（暗証キー等）=`type="text" inputmode="numeric"`＋`enterkeyhint="done"` |

### 10.3 タップ標的

- タップ可能要素の実効ヒット領域は **44×44px 以上**（§2.2-2 の全面化。Apple HIG 44pt / WCAG 2.5.5）。
- 例外: レイアウト再設計が必要な密集部（対局カード右上の絶対配置「変更」等）は M6 の残件として明示し、font-size/padding の底上げで暫定対応する。

### 10.4 キーボード共存（参照）

- フォーカスした入力欄・その直下の候補リストはソフトキーボードに隠れないこと（visualViewport 追従・フォーカス時スクロール）。実装ユーティリティはスライス②（提案書 2026-07-09）で導入予定。
