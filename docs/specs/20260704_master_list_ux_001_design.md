# MASTER-LIST-UX-001 設計 — マスタ一覧の読み取り専用化＋スマホ列絞り

- 日付: 2026-07-04 ／ req: #544 ／ 前段: MASTER-EDIT-FORM-001（?v=70 本番反映済み・#536 クローズ）
- 対象: `shogi_v4.html` buildMasterTabHtml の一覧テーブル部＋CSS。データ層無改変。
- base: orphan clean base `5da7542`（SYNC-V70-ORPHAN-001 取り込み後＝v70 のフォーム実装を包含）

## 1. 背景・原則

外部AI相談（2026-07-04 作者共有）で確立した原則:

> 一覧は「読む場所」。編集は「明示的に変更する場所」。

編集側は v70 で達成済み（行直下の全幅フォーム・セル循環廃止・区分/級セグメント・data-init 差分適用）。本スライスは**一覧側**を仕上げる。マスタは業務上の正本＝「読み取りやすく・縦に比較しやすく・誤操作しにくい」一覧にする。

## 2. 現状の課題（v70 時点）

1. **列数過多**: 選択/氏名/支部員/会費/前回/最終参加 の6列。スマホ実機で窮屈・`overflow-x:auto` フォールバックに頼りがち。
2. **補助情報が独立列**: 「前回」「最終参加」が列を占有し、支部員/会費の縦比較の視線を分断。
3. **削除行の非対称**: 最終列が削除行だけ「削除:日付」に変わる＝列の意味が行によって揺れる。
4. **会費セルが素テキスト**: 支部員セルはチップ、会費は裸テキストで表現が不統一。

## 3. 決定事項

### 3.1 列構成（スマホ基本＝全幅共通・4列）

| 選択 | 氏名（ふりがな＋サブ情報） | 支部員 | 会費 |
|---|---|---|---|

- 選択チェックは**左端固定**（現行踏襲・タップ領域はセル全体 44px 目安に拡大）。
- 前回クラス・最終参加は**氏名セル内のサブ情報行**へ移設（§3.2）。
- 6列→4列で横スクロールを前提にしない（`overflow-x:auto` は保険として残置）。

### 3.2 氏名セルの内部構造（固定3行・行高不変）

```
ふりがな（未入力は「（ふりがな未入力）」アンバー・現行踏襲）
氏名
サブ情報行: 前回:A ・ 最終:2026/6/8   ← 空欄は「前回:－ ・ 最終:－」
```

- サブ情報行は**常に描画**（空でも「－」を置く）＝空欄の有無で行高・列位置が変わらない。
- 削除行はサブ情報行を「削除:2026/7/3」に差し替え（独立列を廃止し非対称を解消）。title に生値（現行踏襲）。
- フォント 10–11px・muted 色。ふりがな/サブ情報とも色だけに頼らずラベル文字を付ける。

### 3.3 支部員・会費チップ（読み取り表示・表現統一）

- 支部員: 「支部員」緑地 ／「その他」グレー地（現行の「他」を**「その他」に変更**＝略語より明確・幅は4列化で確保できる）。
- 会費: 「一般」「中学生以下」「女性」を支部員チップと同型のチップに（`gradeLabel` 流用・「中学」→表示幅次第で「中学生以下」、入らなければ「中学以下」）。
- どちらも文字入り＝色覚に依存しない。チップは表示専用・タップは行タップと同じく編集フォームを開く（title「タップで編集」維持）。

### 3.4 編集導線（v70 方式を維持）

- **行タップ→行直下の全幅編集フォーム**（v70 実機合格）を維持。セルごとの結線（.master-cell-name/-member/-grade）は「どこを触ってもフォームが開く」現行挙動のまま。
- 代替案（記録・不採用）: 外部AI提案の「編集ボタンを右端列に固定」。5列目が復活し列絞りと相反するため今回は見送り。**7/12 大会の実運用で「どこを押せば編集か分からない」の声が出たら再評価**。

### 3.5 スコープ外

- **Undo**: 削除は論理削除＋復元で既に担保。保存 Undo はクラウド即時 push（pushMemberEditToCloud）との整合設計が必要な別課題として起票候補に留める。
- 編集フォーム自体の変更（v70 で完成・無改変）。
- app/ 名簿シート（クラウド側）への同型適用は別スライス候補。
