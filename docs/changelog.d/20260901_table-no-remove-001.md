## TABLE-NO-REMOVE-001: 卓番（第 N 卓）をアプリから外す

- **決定**: 作者裁定（2026-09-01）「**卓番という概念ごと不要**」「沼津の運用に合わせて卓番を全面的に外す。
  他所で必要になったら、そのとき『卓番を使う/使わない』の設定として足す」。
  → **今回は設定を足さない。** 使っていない情報がカードの一等地を占めているのをやめる。
- **撤去（3箇所）**: ①対局カードの卓番バッジ ②印刷の組み合わせ表の「第 N 卓」（`.card-no` の CSS ごと）
  ③参加者の個人ビューの「♟ 3卓　◯◯さん」→「♟ ◯◯さん」。
- **残したもの**: 未入力カウンタ「残り **N** 卓 未入力です（全M卓）」「✓ 全 M 卓 入力済みです」。
  ★ これは**番号ではなく数**で、当日「あと何件入力すればいいか」を見る唯一の指標。
  同じ理由でヘルプ文と「まとめて卓にします」等の**単位・個数としての「卓」は全部据え置き**。
- **派生値も落とした**: `sbFindCurrentMatch` の戻り値から `table` を撤去。③で読み手が 0 になるため、
  残すと「挙動を測っていない pin」だけが残る。`oppId` / `won` は不変。
- **データ移行なし・可逆**: 卓番は配列 index+1 から毎回作る派生値で、`state` にも保存データにも
  `"table"` キーは 0 件。表示を戻せば元どおり。
- **★ 効果は 0px（ブリーフの数字を訂正する）**: cowork はブリーフで「この便だけで −1,440px」と書いたが、
  **実測すると 1px も縮まない**（30名2クラス・375px・実 Chromium で 12,905px → 12,905px、
  カード 182px → 182px）。**ヘッダ行 44px を決めているのは卓番バッジではなく「変更」ボタンの
  `min-height:44px`** だった。あわせて「変更を対戦行の右端へ移す」も試したが、375px では名前欄が
  押されて折り返し、カードは **182px → 186px と逆に伸びる**。
  → **カードの高さの見直しは #942 に全部移る。** 「ボタンを移すだけ」では済まない。
- テスト: 赤くなった5本を書き直した。いずれも**死んだ命題を消し、生きている命題を残した**。
  ① `test_frp_impl_004.js` M3「卓番号は index+1 から描画」→「カードは pairings の順に index 付きで
  描画される」（`wb_A_0_p1` / `wb_A_1_p1` の並びで測る）＋「バッジは描画されない」
  ② `test_tap_target_dense_001.js` S2-1「バッジ→変更の順」→「**変更ボタンが flow のヘッダ行に居る**」
  （★ 44px タップ標的の命題＝S1 はそのまま生存）＋「バッジは残っていない」
  ③ `test_scoreboard_my_view_001.js` M1/M8 → `table` を含めないこと・「次の対戦で**相手が誰か**が分かる」
  ④ `test_scoreboard_inprogress_marks_832.js` C6-8 → `won`/`oppId` は維持・`table` は含めない
  ⑤ `golden_snapshot_001.json` 再生成（差分は**バッジ2枚と justify-content だけ**であることを目視確認）
  ★ `test/test_dayof_unentered_001.js` は**1文字も触らずに緑**＝カウンタを残せている証拠。
  変異5本すべてで赤を実測（バッジを戻す／`table` を戻す／個人ビューに卓番を戻す／
  **カウンタを消す**／変更ボタンの `min-height` を落とす）。
