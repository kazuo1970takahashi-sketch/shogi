## FINISHED-MATCH-FOLD-001: 終わった対局を下段へ畳む

- **問題**: ★**大会が進んでも画面は短くならない。むしろ伸びる。** 30名2クラス・375px の実測で
  進行 0%→100% が **12,905px → 13,565px**。終わった対局が終わる前と同じ大きさで残るため、
  **いちばん疲れている終盤にいちばん長い**という作りだった。
- **作者裁定（2026-09-01）**: **押した瞬間には畳まない。**「次の対局を操作するまでは畳まない」＝
  いま自分がいじった1件だけは上段に大きいまま残す。★すぐ畳むと**押し間違いにその場で気づけない**ため。
- **修正**: `buildCurrentPairingsHtml` を2段に分けた。
  - **上段** … 勝者未入力のカード全部 ＋ 直前に操作した対局が1件あればそのカード。並びは `pairings` の配列順のまま
  - **下段** … それ以外の終わった対局を「`終わった対局（N）　タップで開閉`」の `details` に**1行ずつ**
    （`勝者 ○ − 敗者　[直す]`）。#661（`buildPlayedHistoryHtml`）と同じ native disclosure＝**開閉の JS を足さない**
  - **[直す]** … その対局を**上段へ戻すだけ**。★設計の初稿は「変更モーダルを開く」だったが、
    押し間違いの直しに要るのは**相手の入れ替えではなく勝者の入れ直し**なので、上段へ戻すのが正しい。
    上段へ戻れば既存の勝者ボタンと「変更」がそのまま使える＝**新しいモーダルを足していない**
- **効き**（30名2クラス・375px・実 Chromium・#941+#942 を当てた状態を基準）:

  | 進行 | 畳み無し | **畳みあり** | 削減 |
  |---|---|---|---|
  | 0% | 11,799px | 11,799px | 0 |
  | 25% | 11,975px | **10,670px** | −10.9% |
  | 50% | 12,151px | **9,442px** | −22.3% |
  | 75% | 12,283px | **8,522px** | −30.6% |
  | 100% | 12,459px | **7,290px** | **−41.5%** |

  ★ **画面の性質が変わった**: 元は「進むほど長くなる」（12,905 → 13,565px）。いまは
  **進むほど短くなる**（11,799 → 7,290px）。#941+#942 と合わせて終局で **13,565 → 7,290px（−46.3%）**。
- **★ 覚え方を index ではなく「回戦＋対戦の顔ぶれ」にした（設計上いちばん重要な点）**:
  当初は「直前に操作した対局」を index で持ち、組み合わせが作り直される4経路
  （回戦確定・再生成・クラスリセット・全リセット）で忘れる処理を置いた。
  ★ **その4つを全部消しても検査が緑のままだった**（`setWinner` が必ず上書きするため）＝
  [[redundant-guards-are-untestable]] の型そのもの。**ガードを増やすのをやめ、覚え方を変えた。**
  回戦か顔ぶれが変われば古い値は自動的に一致しなくなるので、**忘れる処理が1つも要らない**。
  バックアップ復元・取り込みのように `setWinner` を経ずに勝敗が入る経路も、これで自然に処理される。
- **保存しない**: `state` にも match にも新しいキーを足していない（メモリ上の値1つ・CLAUDE.md 項目4）。
- **不変**: 未入力カウンタ（畳んだぶんも含めて全対局を数える）／勝者ボタン・「変更」の id と bind／
  文字の床15px／理由ラベル／確定ボタンの無効化条件。
- テスト: `test/e2e/finished_match_fold_943.e2e.js`（実 Chromium）。
  ★ **どちらの段に描かれているか**で測る（`details` の開閉の見た目ではない）。段が移る命題は**実際にクリック**して見る。
  固定している命題: 未入力は必ず上段／直前操作は終わっていても上段／次を操作すると前が下段へ落ちる／
  [直す]で上段へ戻り勝者ボタンがある／カウンタは全対局を数える／回戦確定で下段が空／
  `state` と match に正準形の外のキーが無い（勝敗入力直後と回戦確定後の両方で）／
  顔ぶれか回戦が変われば「触った」記憶は効かない／色・枠は class で持ち inline style を持たない／
  summary と[直す]は 44px 以上／`.fm-*` に新色を足していない（CSS コメントを除いて他所と突き合わせ）。
  各命題は変異を当てて赤になることを確かめてある（index 方式に戻す・押した瞬間に畳む・新色を戻す 等）。
