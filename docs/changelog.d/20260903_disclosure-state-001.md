## DISCLOSURE-STATE-001 (#950): 対局管理の details の開閉を再描画をまたいで保つ

- **問題**: 対戦済みリスト（#661）・暫定成績（#944）・終わった対局（#943）は `renderTournament` が innerHTML を組み直すたびに `open` を決め直していた。幹事が一覧を開いて見ている最中に勝敗を1つ入れると再描画が走り、見ていた一覧が閉じる（いちばん見たいタイミングで閉じる）。
- **修正**: `dsSlot` / `dsKey` / `dsOpenAttr` / `dsRemember` / `dsBind` を新設。利用者の開閉（`toggle`）をメモリ上の `_dsMem` に覚え、次の描画で `open` を決めるときに使う。
  - 既定（スマホは畳む・PC は開く・終わった対局は畳む）は変えない。変わるのは利用者が触ったあとだけ。
  - 記憶の持ち主は `state.results[cls]` の配列そのもの（参照の同一性）。クラスのリセット・進行リセット・全リセット・復元はどれも配列を置き換えるので記憶は自動的に無効になり、キーに回戦を含めるので回戦確定でも既定へ戻る＝「忘れる処理」を置かない（#943 と同じ型）。
  - `state` にも保存データにも入れない（メモリ上だけ）。
  - Chromium は `open` 付きで挿入した details にも `toggle` を1回投げるので、描画時の値と同じ最初の1回は読み飛ばす（覚えると描画時の幅の既定が固定され、幅が変わっても収束しなくなる）。
- **やらないこと**: 幅の境界（600px）をまたいだときの描き直し（#950 の案2）。触っていない details は次の再描画で新しい幅の既定に収束することを実測したので入れない。
- テスト: `test/e2e/disclosure_state_950.e2e.js`（実 Chromium・375px と 1024px）。既存の `test_mobile_played_collapse_001.js` / `test_score_grid_fold_944.js` は open の決め方を `dsOpenAttr` に委ねた形へ追随。
