## TAB-LABEL-WRAP-001: タブ名が折り返すときの折れ位置を語の切れ目にする

- **問題**: 作者「スマホで見ると参加者登録のところが２段になってる」「今は**参加者登**が１段目だから
  格好悪い」。CJK は既定でどこでも折れるため、幅が足りないと `参加者登 / 録` になっていた。
  実測（実 Chromium・`10a052b`）では **360 / 375 / 390 / 414 / 430px のすべてで `参加者登 / 録`**。
  320px では5本とも `対局管 / 理` のように1文字だけが2段目に落ちていた。
  ★ 折り返し自体は避けられない（床15px にした FONT-FLOOR-001 以降・#932 の実測）。
  避けられないなら**折れる場所を選ぶ**、という直し方。
- **修正**: タブのラベルを語のまとまりで `span.tab-w` に分け、`.tab-w{display:inline-block}` を1宣言追加。
  inline-block の内側では折れず、まとまりとまとまりの間で折れる。
  `参加者 / 登録`・`対局 / 管理`・`最終 / 結果`・`会員 / 名簿`・`大会 / 履歴`。
  ★ **ラベルの文字そのものは変えていない**（呼称の短縮は #932 の範囲・用語辞書 §4.1 の改訂を伴う）。
- **なぜ `white-space:nowrap` にしないか**: MOBILE-TAB-001 (#239) が
  「想定外でも折り返しに留めて横スクロールは発生させない」と決めている。実測でも nowrap を当てると
  **320px でページが 15px 横あふれ**し、タブの高さが 58px → 39px（タップ標的 44px 未満）に潰れた。
  inline-block ならまとまり自体が入らないほど狭ければ従来どおり内側で折り返すので、
  **240px まで横あふれ 0**（base と完全に同一の見え方）。
- **効果**: 320〜430px でタブ名が語の切れ目で折れる。**タブ帯の高さは全幅で不変**、
  ページの横あふれ 0、タップ標的 44px 以上（スマホ幅）を維持。
- **既存不適合（本便では直さない）**: 768px では5本とも1行になり、`.tab` の padding 10px×2 + 行高で
  **39px**＝44px 未満。**base でも 39px** で本便は 1px も動かしていないため、e2e では
  「39px のまま」を対照として固定した。直すならタブ帯の設計の話＝別便。
- テスト: `test/e2e/tab_label_wrap_001.e2e.js`（実 Chromium・7幅で `Range.getClientRects()` から
  **実際の行box** を組み立てて折れ位置を読む）。CSS 宣言の有無では折れ位置は測れない。
  変異3本すべてで赤を実測（`.tab-w` の display を消す／span を外す／`white-space:nowrap` を足す）。
  `test/test_dayof_quickwins.js` ⑦ と `test/test_manual_sync_001.js` A1 のタブ名照合を
  **タグを剥がした可視文字列**で行うように直した（生文字列の完全一致だと「割り方」の変更で偽の赤になる）。
  どちらもタブ名を変える変異で赤になることを実測済み。
