## FONT-FLOOR-001: 文字の床を 15px にする（案A・床上げ）

- **問題**: スマホ運用が前提なのに、幹事の3画面で描かれている文字の **8割前後が 14px 未満**だった
  （実測・iPhone 幅 375px / 16名2クラス3回戦: 参加者登録 69.3% / 対局管理 81.7% / 最終結果 89.4%）。
  沼津支部長「スマホで使う前提なんだけど、年寄りには見えない」。
- **修正**: `shogi_v4.html` の `font-size` の px 値のうち **15px 未満のものを 15px に上げる**（床上げ）。
  16px 以上は据え置き＝入力欄の 16px は不変（iOS フォーカス時の自動ズーム防止・STYLE-GUIDE §10.1）。
  ふりがな `rt` は 10px、対局カードの選手名 `.winner-btn` は 17px。
  変更は **font-size の値だけ**（セレクタ・カスケード・DOM・イベント・文言・色は不変）。
- **据え置き**: 星取表 `#scoreboard-view` 配下は**現在の実寸のまま**。横に列が多い表で、床を上げると
  右の列がさらに画面外へ押し出される（現状でも `勝 / 負 / B / C` は横スクロールが要る）。
  列の見せ方を決めるのは別スライス。`#scoreboard-view` にスコープした上書きで据え置く。
  印刷/PDF（対戦成績・組み合わせカード・報告書）は A4 の1ページ収まりを別途調整済みのため対象外。
- **効果**（同条件の実測・ふりがなを除く）: 3画面とも **15px 未満の可視文字 0 文字**。
  ページ高は 参加者登録 +6.0% / 対局管理 +9.7% / 最終結果 +23.8%。横あふれは 320〜1024px で 0。
- テスト: `test/e2e/font_floor_001.e2e.js`（実 Chromium・描画された computed font-size を走査。
  スマホ375 と PC1024 の2幅×3画面＋星取表の実寸照合＝36件）／`test/test_font_floor_001.js`（宣言側の
  静的 pin・許可表は理由付き・自己検査つき＝22件）。変異6本すべてで赤になることを実測済み。
