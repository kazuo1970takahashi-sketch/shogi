## FONT-FLOOR-001: 文字の床を 15px にする（案A・床上げ）

- **問題**: スマホ運用が前提なのに、幹事の3画面で描かれている文字の **8割前後が 14px 未満**だった
  （実測・iPhone 幅 375px / 16名2クラス3回戦: 参加者登録 69.3% / 対局管理 81.7% / 最終結果 89.4%）。
  沼津支部長「スマホで使う前提なんだけど、年寄りには見えない」。
- **修正**: `shogi_v4.html` の `font-size` の px 値のうち **15px 未満のものを 15px に上げる**（床上げ）。
  16px 以上は据え置き＝入力欄の 16px は不変（iOS フォーカス時の自動ズーム防止・STYLE-GUIDE §10.1）。
  ふりがな `rt` は 10px、対局カードの選手名 `.winner-btn` は 17px。
  変更は **font-size の値だけ**（セレクタ・カスケード・DOM・イベント・文言・色は不変）。
- **据え置き**: 星取表 `#scoreboard-view` 配下は**現在の実寸のまま**。横に列が多い表で、床を上げると
  右の列がさらに画面外へ押し出される（現状でも `勝 / 負 / B / C` は横スクロールが要る）。
  列の見せ方を決めるのは別スライス。`#scoreboard-view` にスコープした上書きで据え置く。
  印刷/PDF（対戦成績・組み合わせカード・報告書）は A4 の1ページ収まりを別途調整済みのため対象外。
- **効果**（同条件の実測・ふりがなを除く）: 3画面とも **15px 未満の可視文字 0 文字**。
  ページ高は 参加者登録 +6.0% / 対局管理 +9.7% / 最終結果 +23.8%。横あふれは 320〜1024px で 0。
- **2巡目（Codex P2×3 反映）**: ① `input[type=file]` 2箇所を 16px に（§10.1 は type=file を除外して
  いない。base 時点で 14px＝元からの違反を本 PR で解消）② 静的 pin が px 以外の単位（em/%/キーワード）を
  免除枠の外で拒否するようにした（`.5em` 差し替え変異が緑のまま通っていた穴）③ 星取表の据え置き pin に
  クラス切替タブと行タップ→個人ビューの経路を追加（個人ビューは1文字も測られていなかった）。
- **3巡目**: 大会履歴タブのクラウド閲覧（`#history-content`）のルビも rt 規則が当たらず UA 既定
  50%＝7.5px だった（base でも同値＝既存の欠落・床上げで顕在化）。`#history-content rt{font-size:10px}`
  を1宣言追加し、偽 client（`from().select().eq()` が `{data,error}` の Promise を返す）で実描画経路を
  通す動的 pin を2幅（スマホ=カード / 広幅=表 で builder が入れ替わるため）で追加。
- **4巡目（Codex 2nd レビュー P2×2 反映）**: file input は「宣言が無いこと自体」を静的 pin の違反に
  （消す変異が素通りだった）／クラウド履歴の pin に星取表スナップショット経路を追加（snapshot 空だと
  `.sb-table` が一度も描かれず、履歴限定の 11px 上書きが素通りだった）。
- **5巡目（Codex 2nd P1 = cowork 裁定(a)）**: 報告書専用 helper `buildReportWinnerKindGradeHtml`
  （`buildReportHtml` の1箇所からのみ呼ばれる・画面側は別関数 `buildEntryAttrDisplayHtml`）を
  11px に戻し、帳票 payload（golden）が **base と byte 一致**に復帰することを機械照合。画面側は不変。
  あわせて file input の走査実績を厳密件数（=2）に、星取表 CSS 免除を
  「`.sb-`/`#scoreboard-view` **始まり**のセレクタのみ」に狭めた（他コンテナ起点の上書きは免除しない）。
- **6巡目（Codex 3巡目 P2×5 のうち本 PR 起因の3件・テストのみ）**: ① 星取表 CSS 免除に
  「`~`/`+` 結合子を含むセレクタは免除しない」を追加（前方一致は部分木内に留まることを保証しない）
  ② file input の可視判定に `hidden` 属性を追加（消え方は display:none だけではない・
  visibility:hidden は現物 0 件）③ 免除枠③の前提「報告書専用」を pin 化＝
  `buildReportWinnerKindGradeHtml` の呼び出しがちょうど1箇所・呼び出し元が `buildReportHtml` で
  あることを厳密値で pin（grep は事実であって pin ではない）。残り2件（`font` ショートハンド走査・
  星取表全表示状態の実寸表）は既存の網の粗さ＝別 Issue #936 / #937。
- **7巡目（Codex 4巡目・偽陽性1件の修正で閉じる）**: 6巡目①の `~`/`+` 判定が属性セレクタと
  引用符の中を剥がしておらず、`.sb-table[data-mark="+"]` のような安全なセレクタの属性値の `+` を
  結合子と誤判定して落とす退行（唯一の「正しいものを落とす」型）→ 引用符内→角括弧内→括弧内の順に
  剥がしてから判定。残る P2×5 は静的 pin の設計限界として #939 へ（#936/#937 と同根）。
  **静的 pin は補助であり、担保の主体は実 Chromium で実寸を測る動的 pin**。
- テスト: `test/e2e/font_floor_001.e2e.js`（実 Chromium・描画された computed font-size を走査。
  スマホ375 と PC1024 の2幅×3画面＋星取表 表/タブ切替/個人ビュー＋クラウド履歴閲覧（結果ブロック＋
  スナップショット）の実寸照合＝57件）／`test/test_font_floor_001.js`（宣言側の静的 pin・単位検査・
  input 全種 16px＋可視 file input の宣言必須・許可表は理由付き・呼び出し元 pin・自己検査つき＝33件）。
  変異17本（Codex が使った8本を含む）すべてで赤になることを実測済み。
