# 要件確定ゲート テンプレート (REQUIREMENT GATE v1)

> 目的: **#221 型の事故**（「正しく動くが、合意した要件とは別の問題を解いている」）を実装前に止める。
> このゲートを通すまで実装に着手しない。記入済みインスタンスの正本は **GitHub Issue 本文（真実源）**。

## 使い方
1. 着手前に、担当 orchestrator がこのテンプレを 1 枚埋める（下記「テンプレ本体」をコピー）。
2. **作る前の非相関レビュー = ChatGPT** に「対象外」「受入条件」を渡し、"もう一つの妥当な解釈" が無いか突かせる。
3. **人間 GO**（または ChatGPT 非相関レビュー通過の明示）を得てから実装着手。
4. 記入済みインスタンスは Issue 本文に貼る（このファイルはひな型のみ）。
5. **作った後** = この受入条件を **Codex レビューと merge 前 人間 GO の入力**にする
   （「この diff はこの受入条件を満たし、対象外に踏み込んでいないか?」）。これでゲート間の穴を閉じる。

## 必須フィールド（空欄禁止）
- **受入条件**: 空だと「何ができたら完成か」が無く、#221 を防げない。
- **対象外**: 空だと「作らないもの」が曖昧になり、別解釈で過剰実装が起きる（#221 の核）。

## テンプレ本体（ここからコピー）

~~~
# REQ-<id>: <タイトル>

## 目的（1行・ユーザー価値）
<なぜ作るか。誰のどの不便が消えるか>

## 受入条件（観測可能な挙動で・3〜7件）   ※必須・空欄禁止
- Given <前提> / When <操作> / Then <観測できる結果>
- ...
  （コードや実装手段ではなく、ユーザーが画面で確認できる挙動で書く）

## 対象外（明示的に作らないもの）          ※必須・空欄禁止 ＝ #221 firewall
- <今回は作らない機能・解釈。「一括ではなく逐次」等、紛らわしい別解釈をここで否定する>
- ...

## 変更可能ファイル/領域（ロックと一致）
- shogi_v4.html:<領域> / test/... / docs/... / scripts/...

## 触ってはいけないもの
- index.html / 既存の <既存機能> / production / release / deploy など

## STOP 条件（これを見たら止めて人間に聞く）
- <想定外の差分・別領域への波及・base 不一致・既存実装との重複 など>

## 同領域の進行中（着手時に live 取得して貼る）
- gh pr list --state open の出力（同領域 PR / branch / worktree）
- ホットファイル衝突は git merge-tree で最終判定

## レビュー/merge への引き渡し（#221 firewall を閉じる）
- 作った後の Codex レビュー観点 = 上記「受入条件」を満たすか / 「対象外」に踏み込んでいないか
- merge 前 人間 GO = 同上を確認して承認

## GO 記録
- [ ] 人間 GO            承認者:            日付:
- [ ] ChatGPT 非相関レビュー通過（別解釈の否定を確認）        日付:
- 基準 base SHA:
~~~

## 記入例（参考・#221 を念頭に）

~~~
# REQ-START-LATE-ENTRY: 1局目の途中参加（逐次手合作成）

## 目的
受付中に遅れて来た参加者を、1局目に逐次で組み入れて待たせない。

## 受入条件
- Given 1局目進行中で未割当者が2名以上 / When 「途中参加を追加」 / Then 選んだ2名で対局が1つ append される
- Given 未割当が1名 / When 追加操作 / Then 1名は待機のまま（不正な bye を作らない）
- Given results に既存入力あり / When 追加操作 / Then 既存 winner は不変

## 対象外（#221 firewall）
- クラス一括開始（全員を一度に開始）は作らない  ← #221 はここを取り違えた
- 2局目以降の自動手合いは対象外
- 完全自動ペアリングは対象外
~~~
